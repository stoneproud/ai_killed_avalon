# Independent deterministic adapter review

Reviewed bot.py, test_bot.py, test_bot_attacks.py, the byte-preserved protocol document, and p2/p4 verification logic. No implementation or protocol changes, model calls, old-room reads, or container lifecycle actions.

The production reply path follows the frozen protocol: identical broadcast; clockwise order; Merlin alone receives a nonempty honest local list; other honest seats use none; honest task cards always succeed; fixed preparation rejection and placeholder teams; receipt/recovery reports generated through the original selection tools. Percival's extra knowledge is unused. Attack flags are rejected for Good at construction and task generation additionally requires Evil before playing Fail.

Verification is not based on public confirmation alone. The adapter selects the original first-window reference with p5, reads bytes at the explicit snapshot, checks SHA256 and byte count, runs p6 structural/context checks, and invokes p4 receive followed by check. The original p4 verifies signatures against the registered sender public key before decrypting with this seat's access/id_bus and checking the commitment opening and seat membership. Self-list accounting uses the local original commitment only after a valid first public offer was found. The adapter uses no host-state path or other-seat private key. Registration binds each public SSH/PEM hash to the fixed public registration.

Vote snapshots are saved by quest/attempt and conflicting resaves fail. Later offer/receipt/source/choice reads use those saved snapshots. Recovery starts only after an actual failed quest in the A_in_three branch. Its index counts failed quests from k onwards and excludes the triggering X failure. The real reply path supplements only the leader's pending receipt, or A's pending choice when A is leader; the supplement is the same object attached to that reply.

Existing tests already cover real new-key complete games, both source-consensus recovery branches, A_in_four, private failure after recovery, and invalid/missing first offers that cannot be repaired in a later window. They exercise byte-preserved tools rather than inventing replacement algorithm outputs. I did not repeat those expensive games.

New independent four-second synthetic Git test passed: a valid receipt is read at a fixed historical snapshot; changing the same public pathname in a newer publication cannot affect the old read; a newer blob that disagrees with indexed SHA256 is omitted; and an occupied valid first own slot rejects replacement. This fixture used no keys or old room data.

Nonblocking P2 API hardening: reports(own=...) checks occupancy only after filtering invalid entries. The same synthetic test demonstrated that own can fill a slot whose first indexed blob is already invalid, and the helper itself does not require leader/last-speaker status. Current production reply calls only provide a genuinely pending leader report, so this is not an identified production protocol violation. If other adapters reuse the helper, explicitly require no_first_event for this seat plus the leader's final eligible speech, and reject previously occupied invalid/missing-attachment slots.

Documented limitation: invalid_premises and missing required computation inputs raise ProtocolError. The original document section 7 calls for returning to ordinary Avalon public judgment when protocol premises fail. This deterministic adapter has no generic judgment fallback; an operator/human/external AI must take over. Exceptions must not be described as a requirement in the original protocol to halt the whole game.

Coverage limits: no new container run or signature-forgery end-to-end fixture was executed in this review. Signature enforcement was inspected in the original p4 implementation and its actual invocation chain, while existing end-to-end tests cover valid crypto delivery. No blocking finding in the current production reply path.
